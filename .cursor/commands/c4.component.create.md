# Créer le diagramme C4 — Couche Component

Tu dois **générer ou mettre à jour** le fichier `.spec/05_C4_COMPONENT_LAYER.puml` pour qu’il contienne un **diagramme PlantUML** représentant la **couche Component (niveau 3)** du modèle C4 pour l’application.

## Instructions

1. **Lis** les fichiers `.spec/01_USER_STORIES.md`, `.spec/02_ARCHITECTURE_CHOICES.md` et `.spec/04_C4_CONTAINER_LAYER.puml` (et si besoin `.spec/03_C4_CONTEXT_LAYER.puml`) pour identifier :
   - Le **conteneur** dans lequel zoomer (en général le conteneur principal du système, ex. « Application web » / `blog_web`). S’il y a plusieurs conteneurs, choisis le plus central (ex. l’application web) ou précise dans le titre du diagramme quel conteneur est en scope.
   - Les **composants** (components) à l’intérieur de ce conteneur : modules, couches ou briques logiques (ex. Pages / routing, Layout, lecture Markdown, taxonomie, présentation du site). Dérive-les des user stories et de l’architecture (Next.js, file-based routing, Markdown, etc.).
   - Les **relations** entre composants (qui appelle qui, qui lit quoi), et éventuellement entre un composant et un élément externe au conteneur (ex. lecture de fichiers depuis le système de fichiers / Git au build).

2. **Génère** un diagramme PlantUML au format **C4 Component** :
   - Utilise la librairie **C4-PlantUML** en incluant `C4_Component.puml` (URL standard : `https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Component.puml`).
   - Déclare un **Container_Boundary**(alias_conteneur, "Nom du conteneur") et, à l’intérieur, les **Component**(alias, "Nom", "Technologie", "Description") qui composent ce conteneur.
   - Déclare les **relations** avec **Rel**(source, cible, "Description") ou **Rel**(source, cible, "Description", "Technologie") entre composants (et si pertinent avec un **Container_Ext** ou autre élément externe).
   - Tu peux réutiliser les alias du diagramme Container (ex. `blog_web`) pour le boundary afin de rester cohérent.

3. **Écris** le résultat dans `.spec/05_C4_COMPONENT_LAYER.puml` :
   - Si le fichier existe déjà : remplace son contenu par le diagramme généré (en te basant sur la spec actuelle).
   - Si le fichier ou le dossier `.spec/` n’existe pas : crée-les puis écris le fichier.

4. **Structure type** du fichier :
   - Un bloc `@startuml` / `@enduml` avec un titre adapté (ex. `C4_Component - Application web`).
   - L’`!include` vers `C4_Component.puml`.
   - Un bloc **Container_Boundary** pour le conteneur en scope, contenant les **Component**.
   - Les **Rel** entre composants (et éventuellement vers l’extérieur du boundary).

5. **Réponds** à l’utilisateur en résumant : le conteneur en scope, les composants retenus, leurs relations, et le chemin du fichier créé ou mis à jour.

## Rappel C4 — Niveau Component

La couche Component répond à : *« Quels sont les principaux composants (modules, couches) à l’intérieur de ce conteneur et comment ils interagissent ? »*. Un composant est une brique logique ou technique à l’intérieur d’un conteneur (ex. module de pages, service de lecture Markdown). On ne détaille pas le code (niveau 4 = Code).
