# Créer la documentation C4 — Couche Code

Tu dois **générer ou mettre à jour** le fichier `.spec/06_CODE_LAYER.md` pour documenter la **couche Code (niveau 4)** du modèle C4, en suivant les recommandations suivantes : pas de diagramme Code détaillé à maintenir, mais un **mapping court** entre les composants (niveau 3) et la structure du code.

## Instructions

1. **Lis** le fichier `.spec/05_C4_COMPONENT_LAYER.puml` pour extraire la liste des **composants** du conteneur « Application web » (noms et descriptions des `Component(...)`).

2. **Explore** la structure du projet (dossiers et fichiers clés à la racine, ex. `app/`, `src/`, `components/`, `lib/`, `pages/`) pour repérer où chaque composant est implémenté. Tu peux lister les répertoires et ouvrir quelques fichiers représentatifs si besoin.

3. **Génère** le contenu de `.spec/06_CODE_LAYER.md` avec la structure suivante :
   - **Titre** : Couche Code C4 — Blog (ou nom du projet).
   - **Introduction** (quelques lignes) : rappeler que la couche Code correspond à la structure du code dans le dépôt ; qu’on ne maintient pas de diagramme Code dédié ; que ce fichier sert de mapping entre les composants du niveau 3 et les chemins dans le repo.
   - **Mapping composant → code** : une section (table ou liste) qui associe **chaque composant** du diagramme Component à **un ou plusieurs chemins** (dossiers/fichiers) où il est implémenté. Exemple : « **Pages** — `app/`, `app/[slug]/page.tsx` » ; « **Layout** — `components/Layout.tsx`, `app/layout.tsx` » ; etc. Si une partie du code n’existe pas encore, indiquer des chemins probables (ex. à créer) pour rester cohérent avec l’architecture.
   - **Note de maintenance** : une courte phrase indiquant que ce fichier doit être mis à jour lorsque la structure du code change de façon significative.

4. **Écris** le résultat dans `.spec/06_CODE_LAYER.md` :
   - Si le fichier existe déjà : remplace son contenu par la version générée (en te basant sur la spec et la structure actuelle du projet).
   - Si le fichier ou le dossier `.spec/` n’existe pas : crée-les puis écris le fichier.

5. **Réponds** à l’utilisateur en résumant : les composants mappés, les chemins indiqués, et le chemin du fichier créé ou mis à jour.

## Contraintes

- Garder le fichier **court** (environ une page). Pas de liste exhaustive de tous les fichiers.
- Ne pas générer de diagramme PlantUML ou UML pour la couche Code dans ce fichier.
- Utiliser du **Markdown** simple (titres, listes, tableau si utile).
