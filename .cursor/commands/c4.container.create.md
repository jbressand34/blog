# Créer le diagramme C4 — Couche Container

Tu dois **générer ou mettre à jour** le fichier `.spec/04_C4_CONTAINER_LAYER.puml` pour qu’il contienne un **diagramme PlantUML** représentant la **couche Container (niveau 2)** du modèle C4 pour l’application.

## Instructions

1. **Lis** les fichiers `.spec/01_USER_STORIES.md`, `.spec/02_ARCHITECTURE_CHOICES.md` et `.spec/03_C4_CONTEXT_LAYER.puml` pour identifier :
   - Le **système** principal (celui de la couche Contexte, ex. le blog).
   - Les **conteneurs** (containers) à l’intérieur de ce système : applications ou processus déployables qui en font partie (ex. application web Next.js, site statique servi par le CDN). Dérive-les des choix d’architecture (Next.js, JAMstack, Vercel, etc.).
   - Les **personnes** et **systèmes externes** qui interagissent avec ces conteneurs (cohérents avec le diagramme Contexte).
   - Les **relations** entre conteneurs, et entre conteneurs et éléments externes (qui utilise quoi, qui lit quoi au build, qui héberge quoi).

2. **Génère** un diagramme PlantUML au format **C4 Container** :
   - Utilise la librairie **C4-PlantUML** en incluant `C4_Container.puml` (URL standard : `https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml`).
   - Déclare une **System_Boundary**(alias_systeme, "Nom du système") et, à l’intérieur, les **Container**(alias, "Nom", "Technologie", "Description") qui composent le système.
   - Déclare les **Person** et **System_Ext** nécessaires (mêmes alias que dans le diagramme Contexte si possible, pour cohérence).
   - Déclare les **relations** avec **Rel**(source, cible, "Description") ou **Rel**(source, cible, "Description", "Technologie").

3. **Écris** le résultat dans `.spec/04_C4_CONTAINER_LAYER.puml` :
   - Si le fichier existe déjà : remplace son contenu par le diagramme généré (en te basant sur la spec actuelle).
   - Si le fichier ou le dossier `.spec/` n’existe pas : crée-les puis écris le fichier.

4. **Structure type** du fichier :
   - Un bloc `@startuml` / `@enduml` avec un titre adapté (ex. `C4_Container - Blog`).
   - L’`!include` vers `C4_Container.puml`.
   - Un bloc **System_Boundary** pour le système, contenant les **Container**.
   - Les **Person** et **System_Ext** en dehors du boundary.
   - Les **Rel** entre tous ces éléments.

5. **Réponds** à l’utilisateur en résumant : les conteneurs retenus, leurs relations avec les acteurs et les systèmes externes, et le chemin du fichier créé ou mis à jour.

## Rappel C4 — Niveau Container

La couche Container répond à : *« Quelles sont les grandes parties (conteneurs) du système et comment elles interagissent ? »*. Un conteneur est une application ou un bloc déployable (ex. application web, base de données). On ne détaille pas le code ou les composants internes d’un conteneur (niveau 3 = Components).
